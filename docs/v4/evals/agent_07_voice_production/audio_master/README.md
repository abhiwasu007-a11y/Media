## 1. Scope
The step under test is the `agent_07.audio_master` executor on a **synthetic stem generated by code** from the case's `stem` descriptor (a deterministic speech-like surrogate with the stated integrated loudness, true peak, loudness range, silences and clipping), run through the **pinned FFmpeg build** for the measurements (integration) or through a measurement stub that returns the descriptor values (unit run). `codec_model.post_codec_true_peak_overshoot_db` is the per-pass difference between pre-encode and post-decode true peak that the harness injects, so the ceiling step-down logic is testable without a real encoder. No network, no paid call. Cases carry no dates.

## 4. Deterministic assertions (all cases)
| ID | Assertion |
|---|---|
| A1 | Task Output validates against `amw.task_output` 1.0.0 and, on success, the payload against `agent_07.audio_master.output` 1.0.0 |
| A2 | `status`, `error_code`, `gate_verdict` and `gate_reasons` equal `expected` |
| A3 | the measured post-codec true peak satisfies `post_true_peak_le_dbtp` whenever `gate_verdict = PASSED` |
| A4 | the measured post-master integrated loudness relation holds (PASS inside the configured tolerance, or WARN with the measured value when the tolerance is unset) |
| A5 | master sample count equals stem sample count (`duration_delta_samples = 0`) |
| A6 | the first-pass gain equals `target − measured integrated` to the harness measurement resolution; the pass count is within the cap |
| A7 | per-`check_id` verdicts equal `expected.validation` |
| A8 | no file exists at a final path after a drain, crash or error; a temp file is never renamed on failure |
| A9 | a denial or admission refusal reads or writes no blob and starts no attempt; no TTS key is present in the process environment |
| A10 | no log or output contains secret or content canaries; every metric has `org_id` |

## 5. Judge
None (rubric.md is the owner's human listening rubric).

## 6. Pass thresholds (config `evals.agent_07.audio_master.*`; design defaults)
| Threshold | Value |
|---|---|
| Overall case pass rate | **100 %** (32 of 32) |
| Cases where a `PASSED` master has post-codec true peak above −1.0 dBTP | **0** — mandatory |
| Cases where a clipped, silent, wrong-rate, unlicensed-music or cross-tenant input produces a master | **0** — mandatory |
| Cases where the master duration differs from the stem | **0** — mandatory |
CI fails the PR on any miss. Loudness numerical tolerance for the harness measurement is a test-config value recorded in the run record, not a QC threshold; the QC tolerance `qc.loudness.tolerance_lu` is **REQUIRES REVIEW (Phase 1): calibrate in 3B**.

## 7. Recording fields (per case per run)
`run_id`, `case_id`, `passed`, `assertions` (A1–A10 → pass/fail + detail), `config_version`, `ffmpeg_build`, `measurement_mode` (`stub` / `ffmpeg`), `started_at`, `figure_kind`.

## 8. Open points
- The loudness-normalising and limiting filters are proposals until verified (blueprint §6.4); until then the `ffmpeg` mode runs only the INF-09 measurements on generated reference signals, and the processing cases run in `stub` mode.
- AM-05 and AM-07 assert relations because the exact post-limiter loudness depends on the limiter implementation; exact numbers are added after the 3B calibration.

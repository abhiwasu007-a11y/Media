## 1. Scope
The step under test is the `agent_07.audio_master` executor on a **synthetic stem generated by code** from the case's `stem` descriptor (a deterministic speech-like surrogate with the stated integrated loudness, true peak, loudness range, silences and clipping), run through the **pinned FFmpeg build** for the measurements (integration) or through a measurement stub that returns the descriptor values (unit run). `codec_model.post_codec_true_peak_overshoot_db` is the per-pass difference between pre-encode and post-decode true peak that the harness injects, so the ceiling step-down logic is testable without a real encoder. No network, no paid call. Cases carry no dates.

## 3. Case format and `expected` object
Case file format: evals/README.md §2 with the executor-dataset extension of 27 §6.1 (CCR-024): `input = {"payload": <agent_07.audio_master.input>, "fixtures": {…}}`. CI validates `input.payload` against blueprint §7.3 (python `jsonschema`, Draft 2020-12); `fixtures` holds the stem descriptor (`stem`), the timeline blob facts (`timeline`), `config`, `codec_model`, `admission`, `faults`, `resume_from_checkpoint` and, for music cases, the `music` asset facts. Case IDs use the component prefix `AM-NN` (declared here); `category` carries the `eval_case_category` value.

| Key | Meaning |
|---|---|
| `status`, `error_code`, `retryable`, `wait_reason` | Task Output status and 07 §2 code. A failed gate is `status = SUCCEEDED` (03 §5.3 rule 4, CCR-001) |
| `gate_verdict`, `gate_reasons[]` | payload `gate_verdict` (`PASSED` / `FAILED`, the echo of rule 4) and the failing `check_id`s |
| `gate_results{}`, `remedy_stage_id{}`, `next_action_reason` | per `check_id` whether the result carries `gate: true` (gate checks: `qc.audio.*`, `qc.voice.clipping`, `a07.silence.max_run`, `a07.master.limiter_reduction`; `a07.master.duration_preserved` is process-integrity, `gate: false`); for each failing gate result `remedy_stage_id = s07_voice`; the advisory `next_action.reason` (`gate FAILED: <check_ids>`) |
| `post_true_peak_le_dbtp` | relation: post-codec true peak ≤ this value (−1.0, sourced, 18 §5) |
| `post_integrated_target_lufs` | relation: target of the integrated loudness (−14.0); the verdict is `PASS` within `qc.loudness.tolerance_lu` when set and `WARN` with the measured value when unset |
| `master_sample_rate_hz`, `master_channels`, `codec_profile` | 48 000, 2, AAC-LC with bitrate ≥ 384 000 |
| `duration_delta_samples` | 0 (sync) |
| `gain_db_first_pass`, `passes`, `passes_ge`, `limiter_engaged`, `limiter_gain_reduction_db_gt`, `limiter_ceiling_dbtp_final` | solver results (arithmetic: `target − integrated`) |
| `validation{}` | verdict per `check_id` |
| `music_offset_db_between` | 3B: measured offset over narration-active spans inside the band |
| `master_written`, `admitted`, `attempt_started`, `checkpoint_step_key`, `resume_from`, `partial_file_at_final_path` | file and state effects |

## 4. Deterministic assertions (all cases)
| ID | Assertion |
|---|---|
| A1 | Task Output validates against `amw.task_output` 1.0.0 and, on success, the payload against `agent_07.audio_master.output` 1.0.0 |
| A2 | `status`, `error_code`, `gate_verdict` and `gate_reasons` equal `expected`; for a failed gate the task is `SUCCEEDED` and is never classified `AGENT.INCOMPLETE_OUTPUT` |
| A3 | the measured post-codec true peak satisfies `post_true_peak_le_dbtp` whenever `gate_verdict = PASSED` |
| A4 | the measured post-master integrated loudness relation holds (PASS inside the configured tolerance, or WARN with the measured value when the tolerance is unset) |
| A5 | master sample count equals stem sample count (`duration_delta_samples = 0`) |
| A6 | the first-pass gain equals `target − measured integrated` to the harness measurement resolution; the pass count is within the cap |
| A7 | per-`check_id` verdicts equal `expected.validation` |
| A8 | no file exists at a final path after a drain, crash or error; a temp file is never renamed on failure |
| A9 | a denial or admission refusal reads or writes no blob and starts no attempt; no TTS key is present in the process environment |
| A10 | no log or output contains secret or content canaries; every metric has `org_id` |
| A11 | the `gate` and `remedy_stage_id` flags of every validation result equal `expected.gate_results` and `expected.remedy_stage_id`; the 03 §5.2 schema rule holds (`remedy_stage_id` only with `gate: true`; `WARN`/`SKIPPED` never `blocking`) |
| A12 | `input.payload` validates against `agent_07.audio_master.input` 1.0.0 (CI check, offline) |

## 6. Pass thresholds (config `evals.agent_07.audio_master.*`; design defaults)
| Threshold | Value |
|---|---|
| Overall case pass rate | **100 %** (34 of 34) |
| Cases where a `PASSED` master has post-codec true peak above −1.0 dBTP | **0** — mandatory |
| Cases where a clipped, silent, wrong-rate, unlicensed-music or cross-tenant input produces a master | **0** — mandatory |
| Cases where the master duration differs from the stem | **0** — mandatory |
CI fails the PR on any miss. Loudness numerical tolerance for the harness measurement is a test-config value recorded in the run record, not a QC threshold; the QC tolerance `qc.loudness.tolerance_lu` is **REQUIRES REVIEW (Phase 1): calibrate in 3B**.

## 7. Recording fields (per case per run)
`run_id`, `case_id`, `passed`, `assertions` (A1–A12 → pass/fail + detail), `config_version`, `provider` (`fake`), `model` (`fake`), `ffmpeg_build`, `measurement_mode` (`stub` / `ffmpeg`), `cost_micros`, `currency`, `latency_ms`, `started_at`, `figure_kind` (27 §6.4).

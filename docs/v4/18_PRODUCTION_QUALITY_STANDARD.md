## 1. Purpose and operating principles
1. A viewer must not be able to tell the output from a well-run human-made video in its niche; a slideshow of AI stills with flat narration is not an acceptable output (§1A). YPP enforces inauthentic content at channel level (YT-09), so the standard measures real variety, real sources and human contribution, not just file format.
2. **Deterministic first** (24 §3.3.4, 27 §6.2): every criterion that can be measured by code is measured by code; an LLM judge scores only what code cannot; the human reviewer's score wins on conflict.
3. **Blocking vs advisory.** Compliance, licence, delivery-format and loudness/true-peak checks are `blocking: true`. Checks whose thresholds are unsourced are `blocking: false` (`WARN`) until calibrated in 3B, then promoted by configuration.
4. All results are persisted as `qc_results` rows (04 §5.17) and returned as `validation_results` (03 §5.1); the totals as `quality_scores` rows; measured loudness and true peak also on `renders.integrated_lufs` / `renders.true_peak_dbtp`.
5. In 3A the QC report (all check rows, the 100-point score with per-dimension evidence, cost per stage) is delivered as a downloadable file with the MP4, SRT and thumbnails. There is no upload and no OAuth in 3A (D1).

## 2. Visual sourcing hierarchy and per-shot licence record (§1A.1)

### 2.1 Hierarchy (priority order; `visual_source_tier`, GLOSSARY §6.19)
| Rank | Tier value | Meaning | `licence_source_type` expected | Rule |
|---|---|---|---|---|
| 1 | `A_OWNER_REAL` | owner-made real material: screen recordings, real charts rendered from real historical data, owner photos/footage, owner face/hands when chosen | `OWNER_MADE` (or `CLIENT_SUPPLIED` for client types) | preferred whenever available |
| 2 | `B_LICENSED_STOCK` | licensed real stock footage with commercial rights | `PAID_STOCK` (preferred), `FREE_STOCK` (allowed only with the licence recorded per clip, no indemnification) | paid library whose licence covers monetized YouTube, supports channel registration against claims and gives indemnification is preferred; vendor terms are recorded in `licences` (PR-06 for the candidate vendor) |
| 3 | `C_CODE_MOTION` | charts, maps, kinetic text, diagrams generated by code; brand-consistent templates, content varies per video | `CODE_GENERATED` | charts use real historical data only (§1A.1c) |
| 4 | `D_AI_VIDEO` | AI text/image-to-video clips, short B-roll only where real footage does not exist | `AI_GENERATED` | disclosure decision recorded (YT-06/07); never a real identifiable person or fabricated real event; budgeted per video (§2.4) |
| 5 | `E_AI_STILL` | AI stills with pan/zoom/parallax; last resort | `AI_GENERATED` | never the majority of screen time (check `qc.visual.tier_share_e`) |

Charts (CCR-045): a chart that the code renders from real historical data is tier `C_CODE_MOTION`, `source_type = CODE_GENERATED`, `asset_kind = CHART`; the dataset it is drawn from is an `OWNER_MADE` asset (`kind = DOCUMENT`). Tier `A_OWNER_REAL` covers chart material the owner made himself (e.g. his own screen recording).

Agent 08 sources in this order; falling to a lower rank requires a recorded reason (`qc_results.message` of the sourcing task) saying why every higher rank had no usable item. Agent 09 plans so that rank 4–5 usage stays inside the limits of §2.4.

### 2.2 Per-shot licence record (what must exist for every shot)
A "shot" is one contiguous timeline element on any visual track (video clip, still, chart, graphic, caption card, template). The record is assembled from existing tables; no new table or field is needed:

| Element | Where stored | Required content |
|---|---|---|
| Shot position | Agent 09 shot plan (task output payload; field names fixed in the Agent 09 blueprint) | shot ID, `start_ms`/`end_ms` on the render timeline, `asset_id`, tier, segment tag (`explanatory` / other) |
| Asset | `assets` (04 §5.15) | `visual_source_tier` (NOT NULL for VIDEO/IMAGE/CHART), `source_type`, `licence_id`, `expires_at`, status `ACTIVE` |
| Licence terms | `licences` | `state = ACTIVE`, `covers_monetized_youtube` (NULL = unknown = blocks), `third_party_permission`, `indemnification`, `channel_registration_supported`, `terms_sha256`, `expires_at` |
| Use | `licence_ledger` (append-only) | `asset_id`, `licence_id`, `job_id`, `render_id`, `usage_kind` (`SHOT`, `IMAGE`, `MUSIC_BED`, `SFX`, `VOICE`, `FONT`, `TEMPLATE`, `AI_OUTPUT`), `source_url`/`vendor_item_id`, `used_from_ms`, `used_to_ms`, `expiry_at` |

Notes: (a) The ledger requires a `licence_id` for every row (04 §5.15), so owner-made and code-generated items are recorded against a tenant-held **self-grant** licence row of `source_type` `OWNER_MADE` / `CODE_GENERATED` with `covers_monetized_youtube = true` (decided, CCR-031; `licence_ledger.licence_id` stays NOT NULL, CCR-039 rejected).
**Package-owned and overlay elements (CCR-031, one rule for Agents 08, 09, 10, 11).** Every licensable element is an `assets` row: the platform's code templates, code-drawn glyph sets and brand-sting templates are registered **once per tenant** as `assets` rows (`kind = TEMPLATE`, `source_type = CODE_GENERATED`, `attributes.template_id` / `template_version`, `content_sha256` of the template file; idempotent by `UNIQUE (org_id, content_sha256)`) by the shared asset registry of `amw_core` (L1), against the tenant's `CODE_GENERATED` self-grant licence; fonts are `kind = FONT` rows against a `FONT` licence row (an OFL font is recorded with its licence text, no purchase, rule 8). Ledger rows are written **by the agent that places the element**, at placement time (`render_id` NULL, `task_id`, `shot_id` set; 04 §5.15): Agent 08 for every shot **and** for the Agent 09 overlay track (V2: lower-thirds, caption cards, chapter cards, brand sting, end screen; `usage_kind = TEMPLATE`, one row per overlay interval) and one whole-timeline `FONT` row per brand font used by video or burned-in captions; Agent 07 for the voice (`VOICE`) and, from 3B, Agent 08 for the music bed (`MUSIC_BED`); Agent 11 for its own thumbnail elements (picture, template, font; no interval). Agent 10 writes no ledger rows. **Thumbnails:** a thumbnail asset (no render) passes licence completeness when every picture, font and template asset it uses has ≥ 1 ledger row with `job_id` = the job and no interval. (b) In 3A there is no upload, but the deliverables are intended for later YouTube use, so the licence check evaluates as if the destination were monetized YouTube — **REQUIRES REVIEW (Phase 1): owner to confirm; provisional default as stated.** (c) Voice, music, SFX, fonts and templates are "shots" for licence purposes (`usage_kind` VOICE/MUSIC_BED/SFX/FONT/TEMPLATE; `licence_source_type` `TTS_PROVIDER`, `VOICE_CLONE`, `HUMAN_NARRATION`, `MUSIC_LIBRARY`, `SFX_LIBRARY`, `FONT`).

## 7. Automated technical QC — exact commands and thresholds (§1A.6; INF-09)

### 7.0 Conventions
1. **Runs on** the render worker (`HEAVY_CPU`, `agent_10.technical_qc`, 24 §7.1 `s10_qc`), on the final MP4 and its stems/SRT. No paid call. Never during market hours when run on the VPS (D1).
2. **FFmpeg build.** The commands were syntax-checked against FFmpeg 6.1.1 (a development-environment build, **MEASURED 2026-11-18 locally; not a RESEARCH_LOG entry**). The production FFmpeg version is pinned in the render image — **REQUIRES REVIEW (Phase 1): pinned version; re-run the self-test of §7.11 on it**.
3. **Output location.** FFmpeg filters write their results to **stderr** (`-nostats -hide_banner`); the runner captures stderr per command, stores it as evidence (`qc_results.evidence_ref`) and parses it with the patterns given. A non-zero exit, a missing summary line or an unparseable output is never `PASS`: the task fails (`RESOURCE.RENDER_CRASH` if the process died abnormally, otherwise `AGENT.CRASH`; 07) and is retried per policy.
4. **Verdict mapping.** Sourced threshold → `PASS`/`FAIL` with `blocking: true`. Unsourced threshold → the measured value is recorded in `measured`, the threshold field is `null` and the verdict is `WARN`, `blocking: false`, until the value is calibrated and set in configuration (then it becomes `PASS`/`FAIL`, blocking per config). A blocking `FAIL` is a **gate** result (`gate: true`, optional `remedy_stage_id`, 03 §5.3 rule 4): the task still `SUCCEEDED` and the job goes back to `s10_render` or the named remedy stage (24 §3.3 rule 1, §7.1a); after `limits.max_revision_loops` the job completes with `outcome = BLOCKED_COMPLIANCE` (24 §3.3; CCR-001).
5. Variables below: `$F` = final MP4, `$V` = narration stem (WAV 48 kHz), `$M` = music stem, `$S` = SRT, `$T` = timeline JSON. All times in seconds in tool output; stored in ms (GLOSSARY §3).
6. Detector parameters: where the value is the FFmpeg filter default it is labelled **FFmpeg default** (read from `ffmpeg -h filter=<name>`, 6.1.1); defaults are *starting points*, not calibrated values: **REQUIRES REVIEW (Phase 1): calibrate in 3B pilot** for every detector parameter in this section.

### 7.9 Licence completeness (INF-09 lists the filters; this check is database-side)
Per render, the check lists timeline elements and verifies the ledger. Reference query (names as in 04 §5.15 and §5.18; tenant filter via RLS):
```sql
-- elements: one row per timeline element (shot, music, sfx, voice, font, template) from the timeline for :render_id
SELECT e.element_id
FROM   timeline_elements e                       -- derived from timeline JSON at check time
LEFT   JOIN licence_ledger l
       ON  l.render_id = :render_id AND l.asset_id = e.asset_id
       AND l.used_from_ms <= e.start_ms AND l.used_to_ms >= e.end_ms
LEFT   JOIN licences li ON li.id = l.licence_id
WHERE  l.id IS NULL
   OR  li.state <> 'ACTIVE'
   OR  li.covers_monetized_youtube IS DISTINCT FROM TRUE

   OR (li.third_party_permission = 'UNKNOWN' AND li.org_id IS DISTINCT FROM :tenant_org_id);
```

Pass = zero rows. `timeline_elements` is a transient set built from `$T` (not a table). ## 9. The 100-point quality rubric (§1A.7)

### 9.1 Rules
1. Dimensions and maximum points are fixed by GLOSSARY §6.45 `quality_dimension`: `RESEARCH_ACCURACY` 20 · `STORYTELLING` 15 · `AUDIENCE_VALUE` 15 · `VISUAL_QUALITY` 15 · `AUDIO_QUALITY` 10 · `EDITING_QUALITY` 10 · `THUMBNAIL_METADATA` 10 · `COMPLIANCE` 5 (total 100).
2. **Publish/delivery threshold ≥ 85**, configuration key `quality.publish_min_score` (24 §5; recalibrated against the pilot, §11). The total is the sum of the per-dimension points, using the `HUMAN` row where one exists, else the machine row (`quality_scores` view, 04 §5.17).
3. **Compliance failure = reject regardless of score.** Any of: copyright/licence failure, YPP policy failure, SEBI rule failure (`FIN-R1`…`FIN-R13`, GLOSSARY §6.38), missing or wrong disclosure, misleading claim, fabricated news, unverified medical advice → verdict `BLOCKED` in `compliance_verdicts`; the job cannot be delivered/published; the score is still computed and shown for diagnosis. A human cannot lift a compliance `BLOCKED` through the score; only the recorded human-override path of the compliance gate (04 §5.17 `is_final`, Q5) can, and for finance it requires the `owner_sensitive` workflow (24 §3.4).
4. **Human wins on conflict**: per dimension the `HUMAN` row replaces the machine row; the human total is used for the threshold test. If the machine total ≥ 85 and the human total < 85, the result is below threshold (revise). If the machine total < 85 and the human total ≥ 85, the human total stands, **except** where a blocking technical check failed (a blocking `FAIL` in §7 is never overridden by a score).
5. Row storage: one row per dimension per scorer in `quality_scores` (`max_points` = the dimension's points; `scorer_kind`; `evidence_ref` → the breakdown below). Where a dimension combines deterministic and judge criteria, the machine row has `scorer_kind = LLM_JUDGE` and its `evidence_ref` lists every criterion with its points and kind; a purely deterministic dimension has `scorer_kind = DETERMINISTIC`.
6. Judge discipline (27 §6.2): integer scores against a written `rubric.md`; the judge prompt is versioned and calibrated against human labels from the pilot; the rubric version is stored (`rubric_version`).
7. **3A note (affects a 3A design decision):** Agent 12 (metadata) and Agent 13 are not in 3A (D1). In 3A, `THUMBNAIL_METADATA` is scored on the thumbnail variants (Agent 11) and the working title/description draft carried in the script output; chapters/tags/SEO sub-criteria are scored when Agent 12 exists (3C). **REQUIRES REVIEW (Phase 1): 3A-BLOCKING: confirm with the owner that, in 3A, the 4-point metadata share is redistributed (provisional default below) rather than rescaling the total, because the ≥ 85 threshold is otherwise unreachable without Agent 12.**

## 11. Golden-sample pilot procedure (3B; §1A.10, D1)
